# Benchmark 对比评估

## Overview

把"哪个好"变成可审计的加权证据打分：维度→权重→取证→打分→敏感性→推荐。

## 流程

### 1. 定对象与用途

确认候选集（2–6 个，超出则先粗筛）、评估用途（决定权重取向）与时间语境（版本/年份写死，避免跨版本混比）。

### 2. 定维度与权重

按对象类别给默认维度草案，让用户增删（最多 8 维）：

- 技术/框架：能力匹配、生态与社区、性能、学习/运维成本、安全性、长期活跃度、成本
- 产品/竞品：功能覆盖、价格、集成能力、用户体验、服务与生态、风险
- 方案/架构：达成度、复杂度、迁移成本、可逆性、风险

每维权重 1–5，归一化后展示给用户确认。

### 3. 逐格取证打分

矩阵 = 对象 × 维度，每格：

- `分数(0–5) + 证据引用[n] + 置信度[高/中/低]`
- 取证走 deep-research 检索与交叉验证规则（一手优先；单一社区帖只能给"低"）
- 证据不足的格子标 `?` 不强打分——矩阵完整性让位于诚实性

### 4. 加权汇总与排名

总分 = Σ(归一化权重 × 分数)。并列或差距 <5% 时如实写"统计上难分优劣"，不给假推荐。

### 5. 敏感性检验（推荐的前置门）

对权重最高的 2 个维度各 ±20% 重算：排名不变 → 推荐稳健；排名翻转 → 报告"推荐取决于权重取向"，列出翻转条件。

### 6. 输出与归档

- Markdown 矩阵 + 雷达轴数据写入 `research/<slug>/report-YYYYMMDD.md`（"对比评估"型），INDEX/log 各记一行，log `action:"score"`。
- 用户要可视化 → 转 visual-report（雷达图用本技能的多轴 points 规则）。
- 后续同类对比先读旧 notes.md 复用分数证据，只补增量——与 evolve revisit 同一精神。

## 打分标尺（默认锚点）

| 分 | 含义 |
|---|---|
| 5 | 明显领先，一手证据充分 |
| 3 | 达到可用基线 |
| 1 | 有硬伤或关键能力缺失 |
| 0 | 证据表明不支持/已弃用/已排除 |

## 硬约束

- 每个分数必须挂可点击证据，无证据不打分。
- 禁止为迎合预设倾向选择性取材；对偏好对象同样要找负面证据。
- 维度权重是用户价值判断，模型只提供默认草案与翻转分析，不擅自改权。
