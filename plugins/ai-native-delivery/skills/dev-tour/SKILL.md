# dev-tour — 开发全景图（静态快照）

## 触发

- 起草/确认 plan 后（`## 任务拆解` 或 `## 步骤` + `## 改动方案` 已落盘）→ 生成一次快照。
- Build 阶段每完成一个批次 / 一个任务后重新生成刷新（同名覆盖，快照是纯产物可再生）。
- 关单前做范围对账：图里出现「文档外实际改动」必须先解释或回填 plan。
- 用户说「看不到改哪些文件」「给我看时序/流程/全景」。

## 数据契约（写文档时就这样写）

生成器不另造台账，直接读文档 + git：

1. **步骤**（优先级从高到低）
   - `## 步骤`：`1. **T1 标题**：一句话说明`
   - `## 任务拆解`：`- [ ] 1. 标题` + 缩进的 `- 文件：路径` / `- 判据：…` / `- 留痕：…`；或 `### T1 · 标题` 子标题（正文明细行随步骤收口）。**每个实现步骤至少一个文件；纯验证步骤在标题写明「验证步骤」**
   - `## 改动面` / `## 改动方案` 下的 `### 批次 0a：…` 标题
   - 都没有时：按文件所属架构层分组（**层兜底 = 解析失败信号**，生成器打印「解析命中」行、页面顶部出警告条；应规范标题后重生成，`--strict` 时拒产 exit 1）
2. **每步文件**
   - 在 `## 改动方案` 用 `- **T1**：` 或 `### T1` 与步骤编号对齐，块内写反引号路径。
   - L1 单文件计划可直接在 `## 改动方案` 写 `- \`backend/.../Foo.cs\`：做什么`；每个顶层文件条目自动成为一站。
   - 路径尽量写全；只写 `detail.vue` / `SampleSyncService.cs` 也能按仓库同名文件与步骤上下文解析，但全路径最稳。同名多候选时按步骤上下文打分猜一个：该文件条目带 `pathGuess` 标志（页面打「猜?」不确定徽标）、命中行计「路径猜测 Z 处」——basename 唯一命中是确定性的，不算猜测。
   - 未反引号但带代码扩展名且可消解的中段路径也会被采集：步骤标题/正文/表格行里裸写的 `list/index.vue` 这类 token（含 `/` + 已知代码扩展名 + 能消解到仓库真实文件）会入模归入所在步骤；杂型 token（`if/else` 等）一律拒收。未绑定步骤的文件靠正文兜底归步时（basename 或层词臂）均打 `pathGuess` 标；层词臂仅在恰一个步骤正文含该层词时才绑，多义不绑、留「未分步」可见。
   - 表格行路径也会被采集：`## 改动方案` 的 `| \`path\` | 说明 |` 行归入当前块/批次锚（含 `### 批次` 子节内表格）；无锚时进「改动面（未分步）」。任务行标签支持并集式 `1. S1+S2：标题`（块锚按成员交集命中，括注 `（**S3**）` 同样成锚）；消解不伪造——目录反推/锚点拼接必须落到仓库真实文件，未落库路径原样保留为可见的未解析。
3. **测试文件**：写在 `## 验证计划` 或对应步骤里，测试步骤会自动收口。
4. **依赖**（可选，流程图旁路弧数据源）
   - `## 执行顺序` 里的 `依赖：3 依赖 1；4/5 依赖 2 与 3；8 依赖 4~7；10 依赖全部` 子句行（箭头链行 `1 → 2 → 3` 本身由主链表达，不重复产边）。
   - 或任务行内 `- 依赖：T1、T2`。
   - 编号按步骤序号 / `Tn` / 标签 id 归一；解析不到的引用计入 `deps.unresolved` 并打印警告。
5. **实际改动**：`git diff --base` 自动补状态、行数、diff；文档没登记的文件进「文档外实际改动」，不静默丢弃。

## 生成 / 刷新

```bash
# 静态快照（默认 <项目>/.agents/cache/tours/<type>-<name>.html）
node <插件根>/scripts/gen-dev-tour.mjs workflow/plans/<name>.md

# 对比已提交的整段任务（默认 HEAD = 当前未提交工作树）
node <插件根>/scripts/gen-dev-tour.mjs workflow/plans/<name>.md --base origin/main

# 只看模型（调试解析）
node <插件根>/scripts/gen-dev-tour.mjs workflow/plans/<name>.md --json

# 门禁化：层兜底/无步骤/实现步骤无文件时拒产（exit 1；纯验证步骤按标题豁免）
node <插件根>/scripts/gen-dev-tour.mjs workflow/plans/<name>.md --strict
```

- 根锚定：缺省锚定当前目录的 git 仓库根；从子目录或仓外调用时传 `--root <项目仓库根>`。
- 每次生成会打印「解析命中：直认 X/Y 步 … · 路径猜测 Z 处」行——直认率 <100% 先看是不是标题失约，再决定是否接受兜底归集；命中行之后逐条打印「⚠ 第 N 行：<标题>：<原因>」，把失约定位到行（步骤无对齐文件块 / 文件块锚点未对齐任何步骤 / 依赖引用未解析 / 层兜底触发，对应模型 `parseHealth.issues` 的 `{line,title,kind}`；`pathGuess` 与 issues 一律 advisory，不参与 `--strict` 拒产）。页面顶部警告条消费同一份 issues：按 `kind` 归并成「文件块未对齐 / 步骤缺文件 / 依赖未解析」几类，组内再展开逐行；`step-no-files` 中标题含「验证步骤/单测/UI 实测/静态门」的条目单列为“验证步骤”，不计入待修。
- 快照是单文件 HTML，浏览器 `file://` 直接打开即可联动（点站点/文件/步骤卡/时序消息同步左侧树与右侧说明；`←/→` 切步骤，`Esc` 清除；「跟着流程走」自动播放）。

## 视图

- **全景图**：默认网格（每站一张大卡，按编号阅读）；右上「布局」可切横向时间线；「专注全景」隐藏左右栏，6 站通常两行看完。
- **时序图**：按每步文件的架构层（前端 → API → 应用 → 领域 → 基础设施 → DB）连箭头；测试步骤补虚线验证箭头。
- **数据流图**：从 diff 新增行与文档正文静态识别跨文件数据对象（Dto/实体/表），按架构层泳道显示对象流经的层与文件，并列出「定义步骤 → 使用步骤」的传递边；点击对象联动步骤/文件（数据来自模型 dataflow，schema 2；无识别结果时该视图隐藏）。
- **流程图**：计划 → 步骤 → 验证门 → 关单；验证门读 `## 验证计划`。模型 `deps.edges` 非空时，主链左侧细轨画出声明依赖的旁路弧（已传递归约、主链相邻边不重复画；指向先前行=异常反向虚线），hover 步骤高亮其上下游弧与对端步骤。
- **需求**：跟随「对应入口/spec：…」链接读上游文档（一层不递归，最多 3 篇），渲染本档目标 + 上游 intent/spec/incident 的目标与行为/验收要点（模型 `doc.upstream`）；无上游文档时该视图隐藏，需求叙事只看本档 purpose。
- **验证**：左侧计划清单（`## 验证计划`），右侧实际凭证——本机 `.agents/verifications.jsonl` 优先、仓库 `workflow/verify-evidence.md` 兜底合并（ts+head 去重），按文档日期时间窗取最近 10 条（模型 `evidence`）。关联语义是「任务时间窗内的验证凭证」非逐条绑定；流程图验证门同步显示窗内最近凭证；窗内无凭证时视图隐藏。

## 适用规模（源仓 2026-11-11 实测口径）

| 档位 | buildTour（300 diff 文件注入） | 静态 HTML 体积 |
| --- | --- | --- |
| 10 步 | 317–332 ms | ~100 KB |
| 30 步 | 348–350 ms | ~131 KB |
| 60 步 | 474–483 ms | ~178 KB |

边界声明：实测覆盖 ≤60 步 / 300 diff 文件，且该范围内 build 耗时无拐点（远低于 5s）；超出范围未验证，不凭线性外推下结论。浏览器侧实测（Chrome，file:// 静态页，60 步档）：整页 1868 DOM 节点、加载 289ms、六视图切换各 14–22ms——该量级无需虚拟化。复现基准工具（合成 plan 生成器）暂未随插件分发，数字引源仓实测记录。

## 边界

- 文档是计划面，git 是实际面；两者冲突时图上会分栏显示（计划 / 文档外）。
- 不替代 plan 的验收判据与 `check-scope.mjs`；它只是把同一份事实可视化，不新增真相源。
- 生成物默认在 `<项目>/.agents/cache/tours/`，不提交；要留档用 `--out wiki/...` 或截图，不把 HTML 塞进 workflow/。
- **实时版暂未随插件分发**：源仓的看板服务（`/tour` 实时视图、文档保存自动重绘）、`auto-tour` 自动拉起与用量遥测（`/api/tour/usage`）不在 v1 分发面内——本技能 v1 只产 file:// 静态快照；分发前不写依赖实时面的自动化，也不建轮询兜底。
- 引擎脚本改动照常走 `check-scripts-syntax` 等门（插件形态经 check-loop 接线）；本技能不豁免任何门禁。

## 验收

- [ ] 文档有 ≥1 个步骤；每步至少一个文件，或明确是「验证步骤」。
- [ ] 「解析命中」无层兜底（页面无警告条）；有兜底 = 标题失约，先修文档。
- [ ] 图上「文档外实际改动」为空，或有解释/回填。
- [ ] 四种视图切换无空白；点文件能定位到步骤与 diff。
- [ ] 快照 `file://` 打开六视图可用，顶部无警告条。
