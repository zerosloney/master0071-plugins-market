# Code Refactoring 经典重构手法与安全流程

## 何时用

- 消化 uncle-bob 评审出的 P0/P1 发现，或用户直接点名「把这个函数拆开」「消除这个 switch」。
- 前提：目标行为已被测试覆盖；没有测试则先走特征测试步骤，禁止裸奔。
- 不适用：想改变行为或功能（那是新需求开发）；纯删除收敛（交给 simplify）；架构级重画模块（交给 system-architect）。

## 安全流程（先测后重，一步一验证）

1. **建立安全网**：运行现有测试确认全绿；目标没有测试覆盖时先补特征测试——固定当前实际输出（包括可疑的边界值），只锁行为，不判断对错。
2. **小步原子**：一次只应用一个手法、只改一类结构；每步之后立刻跑安全网测试。
3. **每步验证**：测试不过就回滚本步，查明原因再继续；禁止带着红灯往下写。
4. **提交切分**：每个手法独立成一次提交，信息写明手法与对象，保证任意一步可单独回退。
5. **行为不变判据**：对外可观察结果（返回值、副作用、异常及其类型、日志与输出内容）逐项一致；测试集合不变且全绿。允许常数范围内的性能波动，超出必须记录在案。

## 手法目录

每个手法 = 触发气味 + 机械步骤，按编号引用（如「对 X 应用 R1」），一次只做一个。

### R1 提取函数
- 气味：函数过长；一段代码需要注释才能说明意图；多处出现相同或形近的片段。
- 步骤：新建函数并以意图命名 → 复制代码进去 → 找出局部变量、需要带回的改为返回值 → 原处替换为调用 → 跑测试。

### R2 内联函数
- 气味：函数体与名字一样一目了然，中间层只转发参数；间接层妨碍继续重构。
- 步骤：确认无多态覆写 → 调用点替换为函数体 → 删除原函数 → 跑测试。

### R3 搬移函数
- 气味：函数更多使用另一个类的成员；共变聚类显示它总与别的文件一起改。
- 步骤：在目标处建立同体函数 → 原函数改为委托或直接删除并改全部调用点 → 跑测试。

### R4 提取类
- 气味：一个类管两件事，数据与行为天然分成两组；部分字段与方法总被一起使用。
- 步骤：新建类 → 逐个搬移相关字段与方法（每搬一个跑一次测试）→ 理顺新旧类的引用关系。

### R5 引入参数对象
- 气味：三个以上总是一起出现的参数在多个函数间成群传递。
- 步骤：新建只含数据的参数对象 → 逐个函数把参数组替换为对象（可保留旧签名委托过渡）→ 跑测试。

### R6 分解条件表达式
- 气味：条件及其分支挤在一段长代码里，读三遍才懂。
- 步骤：把条件判断提取为谓词函数（R1）→ 把 then/else 分支各提取为函数 → 跑测试。

### R7 以卫语句取代嵌套条件
- 气味：嵌套三层以上；先决条件检查被埋在深层 else 里。
- 步骤：把异常路径逐个提为开头卫语句并早返回 → 去掉多余 else → 每提一条跑一次测试。

### R8 以多态取代条件
- 气味：同一 switch/if-else 结构在多处重复，分支按类型发散。
- 步骤：先用 R6/R1 把条件收敛到单处 → 建立类型层级或策略对象 → 把一个分支搬成一个实现并测试 → 逐分支搬移 → 删掉最后的条件。

### R9 以查询取代临时变量
- 气味：临时变量只赋值一次，却要在长代码里靠名字传递含义。
- 步骤：把赋值表达式提取为查询函数 → 替换该临时变量的全部使用点 → 跑测试。

### R10 含义自证的命名
- 气味：名字需要读实现才能懂；名字与用途不符。只改名称，不改任何结构。
- 步骤：确认新名字准确表达意图 → 全局改名 → 跑测试。

## 边界与红线

- 只做目录内手法，不自创混合步骤；一个手法未验证完不开始下一个。
- 重命名公共 API、跨模块搬移属于对外可见变更：先停下向用户确认调用方迁移方案，不得自行扩散改动。
- 需要新增第三方依赖才能继续时：停止并上报——重构流程不允许引入新依赖。
- 特征测试只锁现状，不趁机「修正」可疑行为；发现疑似 bug 记录下来单独走缺陷流程。

## 产物

- 一系列原子提交（每手法一次），工作树干净。
- 一份重构记录：每个手法条目 = 编号 + 对象 + 测试结果；并注明修掉了评审报告的哪几条 findings。

## 何时停

- 安全网无法建立（代码无法运行、输出无法复现）：停止并如实回报，不做无保护重构。
- 某手法连续两步验证失败：回滚并停止该对象的重构，改报阻塞。
- 范围扩散到目标目录之外或需要行为决策：停止，向用户确认后再继续。
