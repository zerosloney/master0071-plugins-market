# Agent Git Oracle Git 历史技术债检测

## 何时用

- 需要从演进历史的角度回答「这段代码为什么痛」「该先重构哪里」。
- 用户说「找出经常改坏的地方」「哪些文件反复被改」「这个模块是不是没人敢动」。
- 与 code-analyzer 的复杂度报告交叉，把「数字高」升级为「历史上真的痛」。
- 不适用：没有 git 历史的全新仓库；只关心单文件内部质量的场景。

## 前置检查

1. 确认目标是 git 仓库：`git rev-parse --is-inside-work-tree` 返回 true 才继续。
2. 确认历史足够长：提交数至少几十条，否则统计无意义——如实告知用户后停止。
3. 统一统计窗口：默认 12 个月，可按仓库活跃度调整为 6 个月或全部历史；同一批分析内窗口必须一致。

## 五项侦测

### 1. 变更热点

```bash
git log --since="12 months ago" --name-only --pretty=format: -- <目标路径> | grep -v '^$' | sort | uniq -c | sort -rn | head -20
```

解读：按窗口统计每个文件的被改次数，排名前 20 即变更热点。热点回答「历史把改动集中在了哪里」。

### 2. churn × 复杂度交叉

把热点清单与 code-analyzer 的复杂度热点做交集，按二维矩阵解读：

- 高频变更 + 高复杂度 = 债区（P0）：每次改动都在最危险的地方进行，缺陷概率最高。
- 高频变更 + 低复杂度 = 正常活跃（不处理）。
- 低频变更 + 高复杂度 = 观察项（P2）：没人动它；动它之前先补测试。

### 3. 共变聚类

```bash
git log --since="12 months ago" --name-only --pretty=format: -- <目标路径> | grep -v '^$'
```

对热点清单中的每个文件，统计「与它出现在同一次提交里的其他文件」的频次：

- 总是一起改的 2-4 个文件构成共变组：物理上分散、逻辑上耦合的隐性模块。
- 强共变阈值：共同出现次数 ≥ 该文件窗口内被改次数的一半。
- 共变组跨目录时，是模块边界画错的有力证据，记录并移交 system-architect。

### 4. 代码年龄与孤儿

```bash
git log -1 --format="%ci" -- <文件>
```

解读：距今超过 12 个月没有任何提交、且无对应测试的文件列为孤儿候选。孤儿不等于死代码——可能是稳定的基础设施；用全仓引用检索反查，引用为零的才标记为疑似死区，移交 simplify 处置，本技能不动手删除。

### 5. 提交质量信号

```bash
git log --since="12 months ago" --name-only --pretty=format:"%h" -- <目标路径>
```

解读：单次提交同时改动 ≥ 10 个文件、且提交信息含混（update、fix、wip 之类无具体内容）的占比超过三成时，说明该区域历史上以大锤方式维护，小步重构的回归风险更高——债区优先级应上调，并在结论中明示这一判断依据。

## 产物

一份「热点与债区清单」，固定四节：

1. 变更热点表：文件、窗口内被改次数、是否命中复杂度热点。
2. 债区清单：P0/P2 分级，每条附 churn 与复杂度两个维度的具体数字。
3. 共变组：组内文件、共同变更次数、疑似隐性模块的命名建议。
4. 重构优先级建议：按「债区 → 强共变组 → 孤儿候选」排序，每条注明建议交给哪个技能处理（code-refactoring / system-architect / simplify）。

## 何时停

- 仓库无 git 历史、历史过短或 `git log` 报错：停止并如实回报，不伪造统计数字。
- 浅克隆（shallow clone）或大量文件被 ignore 导致统计失真：先向用户说明局限，再决定是否继续。
- 全程只读仓库历史：不 commit、不 checkout、不改工作区任何文件。
- 每条统计结论必须注明来源命令与窗口参数，禁止凭印象编造热点。
