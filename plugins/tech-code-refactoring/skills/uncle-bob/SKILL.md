# Uncle Bob SOLID 与整洁代码评审

## 何时用

- 重构前对目标模块做质量评审，产出分级问题清单供 code-refactoring 逐条消化。
- 用户说「帮我看看这代码写得怎么样」「review 一下这个文件」「这段代码违反了哪些原则」。
- 不适用：需要动手改代码（交给 code-refactoring 与 simplify）；架构级边界问题（交给 system-architect）。

## 评审流程

1. 读 code-analyzer 的 `report.md`（如有），把复杂度热点文件排进评审队列；没有报告则按用户指定范围评审。
2. 逐文件过「SOLID 气味表」，再过「整洁代码清单」。
3. 每条发现按 P0-P2 分级，写入规定的 findings 格式。
4. 只评审不改动；发现问题留给后续技能修复，评审与修改分离。
5. 有上一轮评审报告时做增量对比：标注已修复与新增的 findings，不重复报告已消除的问题。

评审优先级：先评复杂度热点与债区文件，再评其余目标；一次评审范围以用户指定的目录或文件清单为限，不主动扩大。

## SOLID 五原则气味表

| 原则 | 一句话定义 | 违规气味（肉眼/正则可辨） | 修复方向 |
|---|---|---|---|
| S 单一职责 | 一个类只因一个理由变化 | 类名含 Manager/Util/Helper；一个类同时承担解析、存储、格式化等多种事务；文件超长且方法簇互不相关 | 按变化理由拆出职责单一的类 |
| O 开闭 | 扩展靠加代码而非改旧代码 | 新增一个类型要同时修改多处 switch/if-else；各分支逻辑彼此平行且随类型发散 | 抽出统一接口，以多态取代条件 |
| L 里氏替换 | 子类能无损替换父类 | 子类覆写后抛「不支持」异常或方法体置空；子类收缩了父类承诺的合法输入范围 | 重新设计继承关系，改用组合 |
| I 接口隔离 | 不强迫依赖用不到的方法 | 实现类出现大量空方法体；接口方法很多而调用方只用其中一两个 | 拆成小接口，按调用方需要组合 |
| D 依赖倒置 | 依赖抽象不依赖具体 | 顶层业务类里直接构造具体实现；构造函数硬编码路径、地址、密钥等环境细节 | 构造函数注入抽象，把创建挪到装配处 |

## 整洁代码清单

逐项检查，命中即记一条 finding：

| 检查项 | 阈值 | 记录方式 |
|---|---|---|
| 命名 | 名称自解释 | 名称需要读注释才能懂、或与用途明显不符 |
| 函数长度 | 单函数 ≤ 30 行（软阈值） | 超行列出函数名与实际行数 |
| 参数个数 | ≤ 3 个 | 超出即记录；同类型连续参数建议引入参数对象 |
| 注释密度 | 注释解释「为什么」而非「是什么」 | 大段复述代码的注释、被注释掉的代码块 |
| 嵌套深度 | ≤ 3 层 | if/for 层数超限且无卫语句早返回 |

阈值是默认建议；仓库已有成文规范时以规范为准，并在报告中注明采用了哪个标准。

## 评审输出格式

按文件分组输出 findings 列表；评审范围内无发现的文件也要列出（评级 A、无 findings），保证覆盖面可核对。固定结构：

```markdown
## <文件路径>（评级：A/B/C）

- [P0] <原则或清单项> — <位置：函数名/行号> — <气味描述> — <修复方向一句话>
- [P1] …
- [P2] …
```

分级标尺：

- P0：正在或即将制造缺陷的风险——违反单一职责或里氏替换且已有真实调用方受害、嵌套深到逻辑无法可靠验证。
- P1：明确的可维护性损伤——超长函数、参数爆炸、职责混杂；不立即出错但持续收息。
- P2：风格与卫生问题——命名、注释密度；顺手可修，不单独立项。

文件总评：无 P0 且 P1 ≤ 2 记 A；有 P0 或 P1 ≥ 3 记 B；P0 ≥ 3 或文件已难以稳定修改记 C。

与量化底数的交叉：复杂度热点但 findings 很少的文件，倾向判为「本质复杂」，标注待 system-architect 判断；findings 密集却不在热点的文件，风险排序下调——评审结论必须能被量化报告解释，不能自相矛盾。

## 产物

- 一份完整评审报告：按文件分组、组内按 P0→P2 排序，套用上述固定格式。
- 报告头部给出汇总：P0/P1/P2 总数、A/B/C 文件数、建议最先进入重构的前三个文件。
- 评审范围之外顺带看到的问题只记一行线索，不展开、不扩大评审范围。

## 何时停

- 目标代码无法读懂语义（混淆、压缩、非团队使用的语言）：停止并说明原因。
- 每条 finding 必须能指到文件与位置，可被复核验证；不写「整体感觉不好」类空评。
- 全程不修改任何文件：评审与修改分离，防止既当裁判又当运动员。
